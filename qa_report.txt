QA TEST REPORTCocoaLink MVPcocoa-ecosystem.vercel.appConnecting Cocoa Farmers and Buyers in GhanaTest Date: May 26, 2026Build / Environment: Production (Vercel)Tester: Claude (Automated QA Review)1. Executive SummaryCocoaLink MVP is a web platform whose stated purpose is to connect Ghanaian cocoa farmers directly with local and international buyers, offering escrow-secured Mobile Money payments and (per the homepage) AI plus IoT features. This report documents the results of a structured QA pass across the publicly reachable surface of the production deployment at cocoa-ecosystem.vercel.app.The site presents a polished marketing layer, a working public navigation, and reachable authentication forms. However, the core user journeys that the homepage advertises are not yet functional. The two primary calls to action on the landing page ("Get Started" → Marketplace, and "Smart Farm" → IoT Dashboard) both lead to broken or empty experiences. The Marketplace renders filter controls but no listings, and the IoT Dashboard returns an HTTP 500 server error despite being labeled "LIVE" on the homepage.In total, 17 distinct issues were logged across functional, content, SEO, accessibility, security, and performance categories. Two issues are classified as P0 (release-blocking), four as P1 (high), seven as P2 (medium), and four as P3 (low). The product is not recommended for public-facing demos or investor walkthroughs in its current state; the two P0 issues should be fixed or hidden behind feature flags before any external traffic is driven to the homepage.Severity SummarySeverityCodeCountMeaningCriticalP02Blocks a primary user journey or contradicts homepage claims.HighP14Visible defect users will notice; degrades trust.MediumP27Quality, SEO, hygiene; fix before next release.LowP34Cosmetic, polish, copywriting.Top RisksThe homepage advertises Phase 3 & 4 AI and IoT as LIVE, but the IoT dashboard returns a 500 server error. Any visitor who clicks the prominent Smart Farm CTA hits a broken page.The Marketplace page is empty. The primary Get Started CTA leads to a screen with filter controls and no listings, no empty-state message, and no clear next action.Auth forms lack visible bot-protection, password requirements, password-reset flow, and per-page metadata. None are blockers, but together they suggest the auth layer has not been hardened.Several homepage links (View All News, individual news cards) point to # placeholders, signaling that the page is partly static mock-up.2. Scope, Methodology, and Limitations2.1 ScopeThis pass focused on the publicly reachable, unauthenticated surface of the production deployment. The following routes were exercised:/ (root, redirects to /en)/en/ (homepage)/en/listings (Marketplace)/en/auth/login/en/auth/register (default, ?role=BUYER, ?role=FARMER variants)/en/dashboard/iot (Smart Farm)2.2 MethodologyEach route was retrieved over HTTPS and the response body inspected for content correctness, link integrity, form structure, redirect behavior, error codes, and visible copy. Cross-page consistency was checked for metadata (title, description), navigation, and footer. Findings are classified by severity (P0 - P3) and tagged with the affected area (Functional, Content, SEO, Accessibility, Security, Performance, UX).2.3 LimitationsLive interactive testing through a controlled browser was not available during this pass (permission was not granted for the browser automation tool). The following classes of test were therefore NOT performed and remain open:Form submission, validation errors, and post-submit redirectsAuthenticated routes (post-login dashboard, profile, listing creation, chat, payments)Client-side console errors and uncaught exceptionsNetwork waterfall, Time-to-Interactive, Lighthouse metricsMobile responsive behavior at common breakpoints (320, 375, 768, 1024, 1440)Keyboard-only navigation, screen-reader (NVDA / VoiceOver) traversalCross-browser checks (Chrome, Firefox, Safari, Edge)Penetration tests (SQLi, XSS, CSRF, IDOR, rate limiting)These are listed in section 7 (Recommended Follow-up Tests) and should be executed in a follow-up cycle.3.
